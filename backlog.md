## User Stories

### MLT-26 — завантаження одного WAV

Користувач обирає `.wav`; система читає частоту дискретизації й аудіодані. Некоректний або пошкоджений формат дає повідомлення замість аварійного завершення.

### MLT-27 — завантаження кількох WAV

Користувач обирає кілька файлів для пакетної/паралельної обробки. Кожен коректний файл передається на обробку; помилка одного не повинна переривати решту.

### MLT-23 — фільтрація

Користувач обирає фільтр для усунення небажаних частот/шуму. Результат повертається далі; вихідний WAV залишається незміненим.

Live acceptance criteria 2026-11-08: можна обрати й виконати фільтрацію; результат повертається для подальшого використання; початковий WAV не змінюється. Поточний MLT-5 приймає явний `FilterConfig`, повертає новий `SignalPacket` і не змінює input array. WAV selection/read та user UI відсутні, тому перевірено алгоритмічну межу, не end-to-end story.

### MLT-24 — перетворення Фур’є

Обчислити FFT для аудіосигналу, частотну шкалу та амплітуди; передати спектр для подальшого використання.

Live acceptance criteria 2026-11-08: виконати FFT, обчислити частоти й відповідні амплітуди, зберегти спектр для подальшого аналізу. MLT-5 повертає ці значення у `SignalSpectrum` всередині `SignalPacket`; це in-memory/pickle-compatible результат, без окремого disk persistence.

### MLT-25 — важливі частоти

Знайти домінуючі піки зі спектра, відсортувати за амплітудою та повернути список.

Live acceptance criteria 2026-11-08: аналізувати FFT spectrum, автоматично знайти частоти з найбільшими амплітудами й повернути впорядкований список. `signal_proc` робить це per-channel і сортує за спаданням амплітуди; точний Jira MLT-33 mixed-tone критерій пройшов.

### MLT-29 — багатопроцесна обробка

Використати кілька worker-процесів для незалежних WAV-файлів, щоб обробити великі пакети ефективніше. Аварія одного worker-а не повинна ламати роботу решти.

### MLT-28 — перегляд результатів

Окремо для кожного файла показати ім’я й основні характеристики (тривалість, sample rate, канали), знайдені піки, спектр/графік і статус фільтрації.

## Межі функціональності за планом

У плані цільовим форматом є WAV. Розподілена обробка між комп’ютерами через мережу не визначена. Створення/запис нового аудіофайла не є окремою функцією. Перевірка, що фільтрація не змінює оригінал, є вимогою.

Поточний checkout містить MLT-5. Наявність issue в цій карті не означає, що відповідний модуль чи Jira-задачу реалізовано/закрито.
