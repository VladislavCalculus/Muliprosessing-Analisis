# MLT-4: робота з WAV-файлами

## Моя частина проєкту

Модуль читає один або кілька WAV-файлів. Для правильного файла він отримує
звук і його параметри: частоту дискретизації, кількість каналів, розрядність
і тривалість. Для неправильного файла повертає окреме повідомлення про помилку.
Після цього можна продовжувати читати наступні файли.

Математичний модуль отримує готовий `AudioPacket`: ідентифікатор, назву,
частоту дискретизації та звукові значення. Цей спільний формат уже був у
проєкті. Для показу розрядності є `WavFile`, у якому зберігаються пакет і
параметри WAV. Інтерфейсні вікна й керування процесами належать іншим модулям.

## Як запустити

Після встановлення залежностей за кореневим README:

```sh
.venv/bin/python examples/wav_demo.py
.venv/bin/python -m audio_io mono.wav broken.wav stereo.wav
```

У Windows використовуй `.venv\Scripts\python.exe` замість `.venv/bin/python`.
Перша команда сама створює тимчасові приклади. Для другої команди потрібні
власні файли за вказаними шляхами; шлях із пробілами слід узяти в лапки.

## Що можна показати на захисті

Передумови для всіх перевірок: проєкт установлений, команда запуску працює,
є доступ до папки з тестовими файлами. Для кожної перевірки потрібні файли
із зазначеними нижче властивостями. Фактичний результат записують після запуску.

| № | Сценарій і додаткові передумови | Дія | Успішний результат перевірки |
| --- | --- | --- | --- |
| 1 | Правильний моно WAV: 8000 Гц, 16 біт, 1 с | Передати його програмі | Успіх; 1 канал, 8000 Гц, 16 біт, 1 с |
| 2 | Правильний стерео WAV: 16000 Гц, 16 біт, 2 с | Передати його програмі | Успіх; 2 канали, 16000 Гц, 16 біт, 2 с; канали не змішані |
| 3 | Є два правильні файли й текстовий файл з розширенням WAV | Передати їх у порядку правильний → неправильний → правильний | Три окремі результати; помилка другого файла; третій успішно прочитаний |
| 4 | Є файл WAV розміром 0 байтів | Спробувати його прочитати | Повідомлення `empty_audio`; програма продовжує працювати |
| 5 | Є WAV, у якого відрізано частину даних, але залишено старий заголовок | Спробувати його прочитати | Повідомлення `invalid_wav`; неповний звук не видається за успішний результат |
| 6 | Файлів не вибрано | Передати модулю порожній список через `read_wav_batch([])` | Порожній результат без читання файлів і без помилки |

Шостий сценарій перевіряє поведінку модуля після скасованого вибору; кнопка
скасування в графічному інтерфейсі в цьому модулі не реалізована.

## Прості пояснення до можливих запитань

**Що буде, якщо неправильний файл стоїть посередині?**
Перший правильний файл прочитається. Для другого програма покаже його назву
та помилку. Потім вона перейде до третього. Помилка стосується конкретного
файла, тому решта роботи продовжується.

**Як визначається, що файл порожній або пошкоджений?**
Спочатку перевіряється можливість відкрити файл. Файл нульової довжини одразу
дає помилку. Далі перевіряються заголовок і розміри частин WAV. Якщо заголовок
обіцяє більше даних, ніж є у файлі, або звуковий кадр неповний, файл відхиляється.
Також можливий WAV із заголовком, але без звуку — він теж має окрему помилку.

**Чому недостатньо розширення `.wav`?**
Текстовий файл можна перейменувати на `.wav`, але від цього він не стане звуком.
Модуль перевіряє вміст. Правильний WAV із іншою назвою також може бути прочитаний.

**Чому 8000 Гц і 16000 Гц?**
Це зручні значення для прикладів, які дозволяють побачити різні параметри.
Вони означають кількість звукових відліків за секунду в кожному каналі.
8000 Гц не означає, що файл обов'язково моно, а 16000 Гц — що він стерео.
Кількість каналів задається окремо. Це також не частота самого звукового тону.

**Що означають 16 біт і 1 або 2 секунди?**
16 біт — розрядність одного звукового значення в одному каналі.
1 або 2 секунди — тривалість запису, а не час його завантаження.
Тривалість дорівнює кількості звукових кадрів, поділеній на частоту дискретизації.

**Тиша — це порожній файл?**
Ні. У записі тиші є кадри з нульовими значеннями, тому це правильний звук.
У порожньому файлі кадрів немає.

**Навіщо окремий ідентифікатор?**
Два файли з різних папок можуть мати однакову назву. Ідентифікатор дозволяє
знати, до якого саме файла належать параметри, результат або помилка.

**Чи змінюється початковий файл?**
Ні. Він відкривається лише для читання. Модуль повертає окремий масив значень.
Математичний модуль працює з цим масивом і також не перезаписує WAV.

**Що ще не входить до цієї частини?**
Графічні вікна, кнопки й графіки належать MLT-3, розподіл роботи між процесами —
MLT-2. Ця версія читає звичайні RIFF/WAVE PCM8/16/24/32 та IEEE float32/64.
Інші різновиди повертають зрозуміле повідомлення про непідтримуваний формат.

## Межі перевірки

Автоматичні тести створюють невеликі тимчасові WAV, перевіряють точні значення,
метадані, помилки та передавання даних до справжнього MLT-5. Команди й фактичні
результати наведені в `test/README.md`. Наявність описаного сценарію або старої
картки Jira сама по собі не доводить, що в поточній програмі є баг.
